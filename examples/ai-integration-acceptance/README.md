# 从设计审查到真实验收：配套学习模板

这些文件依据 2026 年 11 月 8 日课堂重写，使用“设备借用系统”作为迁移示例。它们不是老师的原始项目、私有插件、skill 包或可直接启动的应用，也不保证你的项目已经安装任何工具。

## 放在哪里、怎样使用

1. 下载并解压资料包，用 VS Code 打开 `ai-integration-acceptance` 文件夹，先读本页。
2. 在你的项目里新建一个不覆盖现有文件的学习目录，例如 `docs/learning/ai-integration-acceptance/`，复制所需模板。项目已有文档路径时，遵照原项目约定。
3. 先填 `01项目现状与环境检查.md`。所有 `【待填写：…】` 都必须替换；示例业务、角色、路径、命令只能作为填写参考，不能直接假定存在。
4. 让项目负责人确认文档和任务范围，再把 `.prompt` 文件中“可发送正文”复制给实际负责的 Agent。`.prompt` 是普通文本，不是可执行脚本；不要在 PowerShell 中运行它。
5. 每次只处理当前阶段需要的模板。把输出保存在你填写的目标路径，再按验收证据判断完成。

## 文件顺序

| 文件 | 谁在什么时候使用 | 应留下的结果 |
|---|---|---|
| 01项目现状与环境检查.md | 项目负责人/执行 Agent，开工前 | 可验证的环境、规则、路径与基线 |
| 02分层与事务规则补充.md | 负责人/后端 Agent，审架构时 | 与原有约定合并的规则，不覆盖旧规则 |
| 03筛选与跨端设计审查.prompt | 设计 Agent，拆任务前 | 筛选设计、端覆盖矩阵、待确认项 |
| 04模块派单.prompt | 指挥 Agent，设计冻结后 | 可验收的任务卡、依赖与派单顺序 |
| 05真实服务验收.prompt | 验收 Agent，模块接线后 | 服务、接口、页面与数据的证据 |
| 06缺陷卡.md | 发现问题的人，修复前 | 可复现缺陷及回归范围 |
| 07并发暂停与恢复.prompt | 指挥 Agent，并发冲突时 | 实际暂停确认、保留清单、恢复门槛 |
| 08数据导入变更.prompt | 数据/架构 Agent，导入前 | 来源与结构评估、试导方案和证据 |
| 09指挥Agent操作手册.md | 负责人，贯穿整个阶段 | 状态真实、证据可追溯的交付闭环 |

## 示例项目边界

设备借用系统可能包含管理端和借用人端：管理员维护设备、审核借用、确认归还；借用人查询设备、提交申请、查看状态。实际项目可能只有一个端，也可能有更多角色，先核实现状再使用模板。

“登录成功”“截图存在”“pytest 通过”“看板绿色”各自只说明一部分事实。完成标准应同时包含当前范围的实际行为和对应证据。缺少前置依赖时，将卡标为 `blocked` 并注明解除条件，不能假装已完成。

数据库账号用于连接数据库，应用登录账号用于业务登录；它们不是同一类身份。Git worktree 只隔离文件工作目录，不会自动隔离测试数据库、端口、队列、对象存储或浏览器状态。

## 如果跟做失败

- 找不到文档、角色或命令：停止猜测，回到01号检查表补真实路径/名称。
- 没有 PM 工具：使用项目已有看板或本地任务表，保留相同字段；不要编造工具调用。
- 测试报错：先记录原始失败，确认版本、服务、数据库和并发占用，再按06号模板归因。
- 流程不适合现有项目：保留原规则，提交具体冲突与最小调整建议；不要整份替换 AGENTS.md。

无需安装本资料包，也没有统一的启动命令。成功跟做的标志是：占位字段已填、任务和证据路径可打开、真实项目的当前验收条件逐条有结果。
