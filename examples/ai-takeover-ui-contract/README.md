# 旧项目接管、UI验收与文档门禁学习包

依据2026-11-10课堂录屏重新编写，2026-11-13整理。不是老师原始提示词包，不含课堂业务源码。

## 使用路线

1. 用VS Code等编辑器打开你自己的项目，先查看Git状态、AGENTS.md和README。
2. 打开本包`01-接管摸底.prompt`，替换所有尖括号占位内容，发给已有项目Agent。
3. 根据报告填写`03-缺口台账.md`，明确本期范围，再使用`02-项目规则.prompt`。
4. 涉及契约变化时先填`06-富文本变更卡.md`；其他业务可改卡片主题但保留字段。
5. 按项目已核实的命令启动服务，在隔离环境使用`04-真实UI验收.prompt`。
6. 用`05-验收矩阵.md`登记每条AC，再按需使用`07-文档门禁.prompt`。
7. 故障填`08-故障复盘.md`，收尾填`09-交付与续接.md`。

## 怎样判断结果可用

- 每个结论能指到代码、文档或实际执行证据。
- 项目能按记录的命令启动，目标业务从入口走到保存和读回。
- 测试中正常、异常、权限、空数据和旧行为有明确覆盖范围。
- PASS、FAIL、未执行、受阻分开；没有证据不算通过。
- 若报错，保留原始步骤、状态码和必要日志，先定位所在层，再做最小修复。

这里不提供适用于所有项目的安装或启动命令。由Agent检查你的README、包管理文件和环境后填入，不要照抄课堂的路径、端口、账号和表名。

## 使用边界

仅在你已获授权的项目和测试环境操作。保留现有用户改动；生产迁移、公开发布、提交推送是否执行，以当前任务授权为准。本包本身不是执行授权。

课堂的测试数字来自课堂Agent报告，本包不宣称重跑了那些测试。门禁负例演练使用临时夹具或隔离副本，不破坏主工作区。不要把密钥、会话Token或私人数据填进提示词、公共台账和截图。
