# AR 对象接线与运行检查

对应 AR Foundation 6.3.5。先备份场景，再配置。

## 最小对象结构

```text
main
├─ Directional Light
├─ AR Session
│  ├─ ARSession
│  └─ ARInputManager
└─ XR Origin
   ├─ XROrigin
   ├─ ARPlaneManager
   ├─ ARRaycastManager
   ├─ PlaceOnPlane
   └─ Camera Offset
      └─ Main Camera
         ├─ Camera
         ├─ AudioListener
         ├─ ARCameraManager
         ├─ ARCameraBackground
         └─ TrackedPoseDriver
```

这是对象和组件混合表示的接线表，组件不是再创建一个同名子物体。

## 必须填写的引用

| 对象/组件 | 字段 | 内容 |
| --- | --- | --- |
| XROrigin | Camera | 子层级 Main Camera |
| XROrigin | Camera Floor Offset Object | Camera Offset |
| ARPlaneManager | Plane Prefab | 带 ARPlane 与网格可视化配置的平面 Prefab |
| ARPlaneManager | Detection Mode | 本次 Horizontal |
| PlaceOnPlane | Spawn Object | 要生成的 Base Prefab |
| TrackedPoseDriver | 位置、旋转输入 | 正确的移动 AR 设备追踪绑定 |

优先用安装包提供的 XR Origin（Mobile AR/AR）创建入口生成正确相机结构。不要只随便建一个空对象并把名字改成 XR Origin。

课件把 Plane Manager 挂 AR Session 的步骤不适用于此版标准结构；这里挂到 XR Origin。只保留一套活动 XR Origin，旧普通 Camera 和 AudioListener 不再重复工作。

## Base 模板

1. Create Empty 创建 Base，初始 Position0、Rotation0、Scale1。
2. 将要整体显示的地形、人物和模型归入 Base，方向光留外面。
3. 将 Base 存为 Prefab，确认资源存在，再删除 Hierarchy 原实例。
4. 把该 Prefab 拖进 Spawn Object。

课件固定 Origin `(0,10,0)`、Camera Far50 和原尺度是这套场景的安排，不是所有 AR 项目的默认值。Far 不等于 FOV；Y10 也不自动产生俯视。

## Play 与真机分别能验证什么

编辑器可以先检查编译、组件和引用。鼠标 fallback 不会自动产生检测平面；需要模拟环境或真机提供 AR 数据。

手机上：

1. 允许相机权限。
2. 对准有纹理、光线适中的桌面，缓慢移动。
3. 检测区域出现后，在平面内点一下。
4. 预期只生成一份 Base。
5. 再点一次没有新对象，是当前脚本规则。

有画面却没平面，检查追踪/提供程序；有平面却放不出模型，检查触摸、Raycast、Spawn Object；模型大小/位置奇怪，检查 Base 内部坐标和资源尺度。逐层检查，别一起改所有设置。

本脚本没有保存跨次启动位置、没有云锚点、没有拖动和缩放交互。
