# 构建与交付速查

## 公共检查

- 正在编辑正确工程，场景已保存。
- Console 没有阻塞编译的红色错误。
- Build Profiles 激活正确平台。
- 生效的 Scene List 包含已勾选的 main。
- 项目引用的资源、脚本和 `.meta` 保留完整。

## Windows VR

1. 选 Windows Build Profile。
2. 检查电脑平台 OpenXR、目标设备 Interaction Profile。
3. Build 到独立输出目录。
4. 复制整个构建输出目录，包含 exe、Data、UnityPlayer.dll 等实际产物。
5. 在连接 VR 设备的电脑打开 exe，检查设备/runtime、头部追踪和画面。

不要只拷 exe，也不需要为了运行而复制 Library 导入缓存。Issues0 不是头显实测结果。

## Android AR

本次历史配置：IL2CPP、ARM64、Minimum API25、OpenGLES3、ARCore Required、Depth Optional。

1. 安装对应 Unity Editor 的 Android Build Support、SDK/NDK、OpenJDK。
2. Android 标签启用 ARCore，检查实际配置。
3. 区分 Product Name（显示名）、Package Name（应用标识）、APK 文件名。
4. Build 输出 APK，不选择 Export Project 或 AAB 来替代课堂直接安装文件。
5. 本课未启用 OBB 拆分，所以传一个 APK。
6. 文件传到内部存储 `Download/B2026/B2026.apk`，点开安装；安装后从应用列表打开 B2026AR。
7. 允许相机，完成平面识别、点击放置和移动视角验证。

本课使用旧 Input 的脚本并保留 Both 兼容设置；当前 Android 文档标注不支持 Both。新项目宜统一输入方案，修改后重新测试，不把“本次构建成功”当成跨设备保证。

## 发生错误时先找哪一层

| 现象 | 检查 |
| --- | --- |
| JDK 未找到 | External Tools 是否指向当前 Editor 内置 JDK |
| 包已装但 AR 不工作 | Android 页提供程序是否启用、手机支持和权限 |
| 空引用 | 对应组件是否存在、是否被停用、Inspector 引用是否已指定 |
| APK 安装失败 | 架构、最低系统、签名/同包冲突、文件完整性 |
| 放置前看见两份场景 | 是否忘记删除 Hierarchy 的原 Base 实例 |
| 第一次放置后再次点击没变化 | `_isPlaced` 的一次放置规则 |
| 图层/脚本引用丢失 | 是否移动或删除资源时丢了 `.meta` |

构建成功、安装成功、应用启动、真实环境功能正确是不同阶段。每阶段分别观察，不把前一个阶段通过当成后一个阶段也通过。
