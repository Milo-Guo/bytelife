# 练习二：人物为什么动，相机为什么跟

对应正文第 6、7 节。在普通电脑场景副本中操作，不在 XR Camera 上试普通相机跟随。

## A. 先看实际组件

1. 选择 Hierarchy 的 Player，查找 CharacterController、QueryLocomotionController。
2. 展开 BodyParts，查找 Animator 与 Animator Controller 引用。
3. 进入 Play，点一下 Game 确保输入焦点。
4. 试 W/S 前后、A/D 转向、Shift 配合向前跑、Space 跳跃。
5. 同时看根对象 Position 与 Animator 的 Speed、Jump 参数。

本课 A/D 控制转身，不能把它当成固定横移。位移和动画是两条分工不同的链。

## B. 阅读四组关键代码

```csharp
float inputY = Input.GetAxis("Vertical");
moveDirection = new Vector3(0, 0, inputY);
moveDirection = transform.TransformDirection(moveDirection);
controller.Move(moveDirection * Time.deltaTime);
```

这是原脚本中连续处理阶段的简化摘录，不是可单独运行的新控制器。实际代码在 Move 前还处理速度、跳跃与重力。

依次解释：读前后输入 → 得到人物局部方向 → 转为世界方向 → 根据帧时间移动。

原示例的空中重力每帧固定减值，没有乘 deltaTime，因此不能笼统说整个控制器完全与帧率无关。

## C. 验证父子层级跟随

1. 退出 Play，保存并记录 MainCamera 的层级和 Transform。
2. 这次 HS2022 的 Camera 在 Player 下，局部位置为 `(0, 2, -4.5)`，俯角约 15°，未挂跟随脚本。
3. 把 Camera 临时拖到根层级，保留当前位置，再 Play 并移动人物。
4. 观察跟随是否消失，然后退出并恢复原父级和局部变换。

预期：原来的跟随来自父子变换，不是因为文件夹里恰好有 SmoothFollow.cs。

## D. 隐藏模型时要保留谁

停止 Player 会连同子级相机一起停止。停止 BodyParts 不会停止根对象，但 Animator 也可能在被停止的子对象上。

本课旧控制器默认用 GetComponentInChildren<Animator>() 查找活动子对象，因此 BodyParts 启动前失活可能导致找不到 Animator。若继续完善，可只关闭身体 Renderer 隐藏外观，或明确处理 inactive 查找和空值，然后重新运行验证。此项是静态审计风险，并非已复现的头显故障。
