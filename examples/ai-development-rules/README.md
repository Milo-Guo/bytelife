# AI 开发规则：可复制的入门模板

本目录配套 ByteLife 的 10 月 26 日课程笔记。**所有文件均为整理者补充示例，不是老师原件，也不是课堂生成文件的原样备份。**先复制、检查、补齐，再用于自己的项目。

模板不包含应用程序，不安装依赖，不连接任何服务，也不会替你提交或发布代码。

## 先认清每份文件

| 文件 | 用途 |
| --- | --- |
| `00-env-setup.prompt.md` | 在 AI 编程工具的聊天框粘贴使用的初始化提示词 |
| `starter/CLAUDE.md` | Claude Code 的简短入口示例，显式导入同目录 AGENTS.md |
| `starter/AGENTS.md` | 通用工作原则与需要填入的本项目事实 |
| `starter/docs/README.md` | 需求、设计、测试、部署、验收六份文档的索引 |
| `starter/docs/01…06` | 带“待填写”的练习文档；课堂演示的是空文件，本包增加了填写提示 |
| `规则验收清单.md` | 检查内容、加载情况和真实执行结果 |

`starter` 是存放模板的文件夹。用于目标项目时，放进去的是它**里面的文件**，不要让规则留在目标项目的 `starter/` 子目录里。

## 路线一：手动复制，先用于一个练习项目

1. 打开 Windows 文件资源管理器，新建一个练习文件夹，例如 `C:\learn\rules-practice`。这是示例路径，可以换成你自己的空文件夹。
2. 在 VS Code 点击 `File > Open Folder…`（文件 > 打开文件夹），打开刚建的文件夹。
3. 从本包的 `starter` 里复制 `AGENTS.md` 和 `docs` 到该文件夹根目录。使用 Claude Code 且需要本包入口方式时，再复制 `CLAUDE.md`。
4. 在 `AGENTS.md` 中填写项目名、技术栈、真实路径和启动／验证命令。尚未决定的项目写“未确认”；空项目的目录方案写“拟定，未创建”，不能写成已经存在。
5. 按实际开发进度填写 `docs`。初始化时无需把六份业务文档编满，更不能把“待填写”当成已完成。
6. 在 AI 工具中打开**目标项目**的新会话，检查工具实际加载了哪些规则文件；再按验收清单检查。没有自动加载功能的工具，可以在会话中明确附上需要的规则文件。

已有项目同样可以用，但先检查原有 `CLAUDE.md`、`AGENTS.md`、`docs` 以及更具体的目录规则。遇到同名文件不要覆盖：先比较内容，把仍有效的约定保留下来，合并本次确实需要的部分。保留项目现有目录，不为套模板搬文件或重构。

## 路线二：让 AI 根据实际项目写规则

1. 在 AI 编程工具中打开要整理的项目目录。
2. 打开本包 `00-env-setup.prompt.md`，先填开头的信息与授权范围。
3. 将整份提示词复制到聊天输入框，作为普通消息发送。**它是文本模板，不要求存在 `/00-env-setup` 命令，也不依赖安装插件。**
4. 检查 AI 的只读扫描结果：已有文件是否真实存在？新目录是否标为拟定？未确定的版本是否仍标为未确认？
5. 本轮允许创建时，核对实际生成文件和差异；本轮仅允许扫描时，先看候选内容，再自行决定后续采用哪些。
6. 用 `规则验收清单.md` 收尾。文件写出来、工具读到它、修改真正遵守它，是三件分别要检查的事。

在目标项目的 PowerShell 中，可以先检查位置和文件：

```powershell
Set-Location 'C:\learn\rules-practice'
Get-Location
Get-ChildItem -Force
```

成功标志：输出的是你选定的项目路径，列表中有刚放入的规则文件和 `docs`。如果这是已有 Git 仓库，再运行 `git status --short` 看修改范围；不是 Git 仓库时，不必为了使用模板自动执行 `git init`。

## 关于 CLAUDE.md 与 @AGENTS.md

本包 `starter/CLAUDE.md` 含有代码围栏外独立一行 `@AGENTS.md`，用于**支持这项语法的 Claude Code** 显式导入同目录规则。其他工具是否识别文件名与导入语法，要看各自说明；在聊天里提到文件名，也不等于已经自动加载。

Claude Code 的规则加载取决于版本和设置，不能一概说它只认某一种文件名。采用本包入口后，检查会话中已加载的文件；不要只用“AI 说读过了”代替工具的加载信息。官方依据：[Claude Code 的文件导入与规则说明](https://code.claude.com/docs/en/memory#import-additional-files)，核对日期 2026-10-27。

## 怎样知道自己做对了

- 规则中的每个真实路径都能在项目中找到，或者明确标为“拟定／未确认”。
- 命令有执行目录、前提和成功标志；未运行的命令没有“已通过”的记录。
- 没有为了写文档改业务代码、安装包、配置、数据库或 Git 历史。
- 缺少测试或运行环境时，写出原因和下一步，不用虚构输出补空白。
- 规则只是工作约定；它不能代替工具权限、测试、人工复核或真实的功能验收。
