## 2. 当前可以说明的责任边界

| 部分 | 负责 | 不负责 |
| --- | --- | --- |
| 界面/输入入口 | 收集日期金额、展示结果、提示错误 | 不自造保存成功；不单独决定分类与统计规则 |
| 业务规则 | 金额/日期/分类合法性、排序、按月计算 | 不负责部署或界面装饰 |
| 数据读写 | 按最终存储方案执行保存、读取、更新、删除，报告失败 | 不擅自插入样例数据或删除真实数据 |
| 存储设施 | 按选定方案保存数据 | 不决定产品范围或用户权限 |

业务规则通过明确的数据访问接口使用存储；界面不应在多处重复计算不同版本的月合计。小项目可在少量文件中保持这些职责，不必为了画四层而拆出复杂工程。

如果最后选择浏览器本地方案，要明确数据受当前设备、浏览器与网站数据清理影响。如果选择服务端方案，还需确定接口认证、授权和部署；这些不是本示例已经做好的功能。

1. 先回答使用设备、断网要求、预算和恢复目标。
2. 比较能满足这些约束的最少方案；已安装或会用什么只是决策依据之一。
3. 确认选型后再补真实目录、数据结构、读写流程、错误处理及启动命令。
4. 最后用 F/AC 表核对覆盖，不添加 NX01—NX04。

## 5. 如果以后选择 FastAPI，术语怎样分

这只是解释课堂术语，**不是本记账本已经选定 FastAPI**。

| 术语 | 含义 |
| --- | --- |
| module / 模块 | 一组业务功能，例如“支出记录”；不能与 model 混为一谈 |
| router | HTTP 路由入口，接收请求并调用适当逻辑 |
| service | 业务规则与流程，例如核对能否修改、怎样计算 |
| CRUD / repository | 数据访问函数，CRUD 为 Create、Read、Update、Delete |
| ORM model | 描述数据库映射的模型；ORM 是对象与关系数据之间的映射工具 |
| request/response schema | 定义及校验输入、输出的数据形状，常用 Pydantic；不是连接数据库的一层 |

schema 可以被入口及业务代码引用，不应机械画成 `router → service → model → schema → 数据库`。FastAPI 不要求所有项目必须使用同一套目录，更不会只因选了框架就自动完成合理分层。

如果增加了服务端，前端校验用于及时提示，服务端必须独立校验不可信输入；数据库约束作为最后一道一致性检查。只隐藏按钮不能代替服务端授权。
