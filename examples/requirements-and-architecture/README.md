# 需求与架构课：个人记账本练习包

这是依据 10 月 28 日课程思路重新编写的练习材料，**不是老师原文件，也不是已经实现、测试或上线的软件**。课堂举过记账系统的例子；这里的字段、编号、样例金额和取舍由整理者补充。

## 先打开什么

1. 打开 Windows 的文件资源管理器，新建一个独立空文件夹，例如 `文档\学习练习\money-notes`。不要在正在使用的项目中覆盖文件。
2. 打开 VS Code，点 `File → Open Folder`（文件 → 打开文件夹），选择刚才的 `money-notes`。
3. 把本包的 `docs` 文件夹、两份 `.prompt.md` 和审阅清单复制进去。保留原来的文件名，便于引用。
4. 第一次先阅读 `docs/01需求文档.md`。它是一个供练习的假想基线，**“示例已定”不代表用户已经确认了自己的真实需求**。
5. 如果你的实际项目已有 `AGENTS.md`、`CLAUDE.md` 或其他规则文件，先阅读并引用，不要用本包覆盖。空目录没有规则文件就如实告诉 AI，不要求 AI假装已经读取。

本阶段只编辑文档，没有必须运行的安装命令，也不需要购买服务器。

## 第一轮：把想法变成需求

在你使用的 AI 编程工具中选择同一个练习文件夹，新开一个“需求”会话。打开 `01需求访谈.prompt.md`，填写所有方括号，再复制整份内容到会话。

让 AI 先复述目标、提出关键问题。回答后再让它把草稿保存到实际指定的需求文件。已有文件应先比较差异，确认再覆盖。**不要把示例记账本当成你必须采用的产品。**

成功标志：文件确实出现在 VS Code 的 `docs` 下；每条功能都有角色、边界、优先级和对应 AC；你逐条读过并确认。聊天里出现一段文字还不等于已经保存。

## 第二轮：从需求交给架构

1. 需求已确认后保存文件，并记下版本或日期；关键待定项没有解决时，不要声称可以直接开发。
2. 在同一个项目中新开“架构”会话。打开 `02架构设计.prompt.md`，填写**真实存在**的需求文件和规则文件路径。
3. 让 AI 先报告它读到了哪些文件、哪些决定已经确定、哪些尚未确定，再编写架构草稿。
4. 检查架构是否能逐条对应 F 和 AC，是否偷偷加了登录、付费、云同步或多租户等范围外功能。

新会话不会自动继承上一轮聊天的全部结论。文件是交接依据，旧聊天可以保留，不需要删除。

## 文件用途

| 文件 | 用来做什么 |
| --- | --- |
| `01需求访谈.prompt.md` | 先问清楚做什么、不给 AI 默默拍板 |
| `docs/01需求文档.md` | 完整小示例：3 个模块、6 个功能、12 条 AC |
| `02架构设计.prompt.md` | 根据已确认需求和真实规则讨论怎样做 |
| `docs/02架构设计.md` | 架构准备示例，保留未决定的技术选型 |
| `需求审阅清单.md` | 阅读、确认、交接前逐项核对 |

## 常见卡点

- **AI 找不到文件**：在 VS Code 左侧右键文件，点 `Copy Relative Path`（复制相对路径），把结果重新给 AI，检查当前打开的项目目录。
- **AI 直接写代码**：要求停在本阶段文档，先列出未经确认的决定和已产生的文件差异；不要直接删除你的原文件。
- **需求名称不一致**：统一项目名称和文件路径，保留版本记录，再重新审阅引用。
- **输出太空泛**：拿一条 F 追问“什么前提、做哪个动作、会出现什么结果、哪里能证明保存成功”。
- **功能太多**：把建议移到“候选/待确认”，没有确认就不放进本期范围。

以后开始实现时，在实际工程目录按已选技术栈执行运行与测试命令；本包没有提供应用，不能用“文档写完”替代“软件跑通”。
