# 阶段核对表

## 开始任何一阶段

- [ ] 软件当前项目目录正确；VS Code 打开的也是同一目录。
- [ ] 现有规则、文档路径、版本已读；没有平行维护两份需求。
- [ ] 已有项目检查改动，保留用户工作。
- [ ] 本会话修改范围清楚；其他会话没有同时写这些文件。

## 00 规则

- [ ] 栈与分层来自已确认决定；空项目不伪装已有代码。
- [ ] 两份规则无互相冲突；复制其他项目的规则已逐项比较。
- [ ] docs/README 列真实文件、状态和版本；空骨架标未完成。

## 01 需求

- [ ] 每个 F 有角色、场景、行为、范围、优先级、出处和 AC。
- [ ] AC 能判断对错，包含失败/边界；目标分数不当成考试保证。
- [ ] F 编号稳定，新增不复用；已拍板与待确认分开。
- [ ] AC 只在 requirement.md 维护，feature-list 引用并保留真实进度。
- [ ] Q 回答已写回正文、AC、变更记录，不只留在聊天。

## 02a 架构和接口

- [ ] 需求版本与架构引用一致；新业务已回需求确认。
- [ ] 前端、管理网页、后端、数据库职责可解释。
- [ ] 事务、数据访问、权限、会话撤销、日志清楚。
- [ ] 主观任务有领取、超时、重试、恢复与复核设计。
- [ ] 接口有身份、权限、输入、输出、错误、数据归属和幂等约定。

## 02b 数据库

- [ ] 表/字段/约束能追踪到实际功能或已确认技术需要。
- [ ] 复合主键与外键没有混淆；不加外键时写明补偿校验。
- [ ] 时间、状态值、历史快照、敏感字段策略清楚。
- [ ] SQL 与说明分文件；版本方言明确。
- [ ] 生成、静态审阅、隔离执行、正式变更分开记录。
- [ ] 没有执行就写未执行；执行结果记录真实版本与目标。

## 交接 02c 和开发

- [ ] 按所选 F 读 AC、接口和表说明；冲突已解决或列为阻塞。
- [ ] 本功能页面、状态、校验、失败处理和测试设计完整。
- [ ] 开发任务包含范围、输入、输出、AC 和验证方法。
- [ ] 文档、实现、测试、部署分别标状态，不用一个“完成”混写。

## 在项目根目录只读核对

```powershell
Get-Location
Get-ChildItem -LiteralPath .\docs -Recurse -File |
    Select-Object FullName, Length, LastWriteTime
Get-Content -LiteralPath .\docs\01-requirement\requirement.md -TotalCount 30
```

若实际路径不同，先调整路径；文件 0 字节或只有标题时不满足阶段交付。Git 仓库可再用 `git status`、`git diff` 查看实际修改。本包未附业务程序，以上命令不证明系统可以启动。
