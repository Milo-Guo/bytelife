# 增量变更交接模板

把尖括号内容填好再交给当前阶段会话。

```text
本次只做增量修改，不重跑整个初始化或需求问卷。

项目根目录：<实际目录>
当前单一写入会话：<会话名>
其他相关会话状态：<已停止写入 / 仍在运行则先协调>
现有改动：<用户修改及需要保留的文件>

需求文件/版本：<路径、版本>
架构文件/版本：<路径、版本>
接口文件/版本：<路径、版本>
数据库文件/版本：<路径、版本>

已确认变化：<业务原话和决定，保留 Q 编号>
涉及 F/AC：<已有编号；新增待按最高编号追加>
本期不做：<NX 或范围>
本会话可修改：<明确文件>
本会话只读：<明确文件>
未决问题：<影响、是否阻塞>

先读取以上文件，列出差异和影响。
保留未受影响的决定、编号、人工备注和真实进度。
业务新增必须回需求确认；不要仅在架构或表里悄悄增加。

依次核对需求、架构、接口、数据库、功能设计和测试。
本会话范围外的改动列入交接清单，不同时启动多个写入者。
未授权的数据库执行、发布或外部写入不从“继续设计”推导。

完成后：列修改文件/版本、影响 F、检查结果、未运行项、
未完成项、下一会话应该读取的文件，以及该阶段能否开始。
```

## 如果已经发生两会话覆盖

1. 停止相关写入，不立即重跑全部模板。
2. 比较磁盘上的内容、Git diff/历史或备份，确认各方已经写了什么。
3. 找出冲突决定，按已确认需求合并，保留尚未解决的问题。
4. 由一个会话完成修订并核对引用，记录版本后再交给下一会话。

不要把取消任务等同于撤销文件写入，也不要自动选择时间更新较晚的一份为正确版本。
