# 指挥Agent做02c：操作手册

本手册为整理补充，工具可以替换。重点是Agent能读取你自己的项目，输入与输出都有真实文件依据。

## 1 打开同一个项目

资源管理器确认目录；VS Code用`File → Open Folder`打开；Hermes或其他Agent选择同一目录。已有项目先运行`git status`，确认当前变更，不覆盖已有工作。

在自己的项目中复制和填写本包提示词，一端一份。不要直接在下载包中把自己的项目文件混进去。

## 2 先发输入核对

```text
本次只做[填写端]的02c功能设计。
先读项目规则，列真实需求、架构、接口和数据库依据的路径、版本、正文是否非空。
列本端F/AC、目标输出、冲突和待确认。关键输入缺失先指出，不猜字段。
```

成功标志：真实文件清单及本端范围清楚。失败先看当前目录、文件名和引用路径，不能把不存在的文件名当实际依据。

## 3 发送已保存的提示词

```text
请读取已填写的prompts/02c-web.prompt（换成真实路径）。
按已确认输入生成本端设计，按七项逐功能写入实际目标文件。
分批时列完成与剩余编号，最后列AC映射、接口缺口、待确认和变更文件。
```

若工具不支持读文件，粘贴填好的全文。生成后在VS Code打开真实文件，确认正文非空、路径正确。

## 4 抽查一条完整流程

```text
从一个F出发，反查七项、AC、API与表字段。
确认请求和成功失败响应属于同一API，前后端校验分别写清。
给出文档位置和证据；无证据列缺口。
```

若只有握手API示例却缺登录入参，继续补真正的登录契约。不要让接口名称相近掩盖缺口。

## 5 遇到检查失败

```text
请读取具体失败输出，指出对应的文档或检查规则。
区分真实遗漏、字段冲突、编号错误和检查器误判，做最小修订。
报告改动文件、重跑命令及真实结果；再抽查一条完整流程。
```

不以“检查全绿”代替应用运行和安全验收。生成文件若来自脚本，同时检查生成源。

## 6 加需求时同步

使用本包变更同步清单。业务阈值没确认先列Q，默认建议保持建议状态；再按影响同步需求、架构、API、数据库和各端设计。

## 7 设计完成再拆第一张开发卡

```text
基于已确认版本，按依赖拆当前模块的任务卡。
列F/AC/API、文件范围、测试方法、完成证据、前置依赖和阻塞项。
先给第一张可独立验证的小卡。未定契约的卡保留阻塞状态。
```

开发后让Agent读取真实工程配置，给出工作目录、启动/测试命令、环境变量名、成功标志与错误日志位置。勿凭空沿用其他项目的命令或口令。

## 8 中断后继续

```text
请先读取交接记录和当前真实文件。
核对项目、端、上游版本、已完成F/AC、待确认Q、检查结果与未偿缺口。
说明与交接时相比发生的变化，再继续下一步。
```

保留检查日志和变更差异。需要回退时先检查用户当前工作，不执行清空或强制覆盖。
