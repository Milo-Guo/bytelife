# TDD、Agent 派单与交付：配套学习文件

这套文件根据 2026 年 11 月 6 日课堂录屏重写，用来把已有需求和设计交给 Agent 执行。它不是老师的原始提示词、项目源码、PM 插件或 `project-doc-lifecycle` 技能安装包；不含自动看板、后台派单或任何运行脚本。

示例使用“设备借用管理系统”。角色、编号、路径、接口和命令都必须以你自己的项目为准；文中的示例不代表这些文件或接口已经存在。

## 先做这三件事

1. 用 VS Code 打开你的真实项目根目录。如果目录不是 Git 仓库，不要为了照模板就自动建仓，先确认自己的版本管理方式。
2. 在 VS Code 的 `Terminal → New Terminal`（终端→新建终端）里执行适用的只读检查：已有 Git 仓库可运行 `git status --short --branch`，确认已有改动；运行命令前核对当前目录。
3. 先填写 `01-开发前检查表.md`。让 Agent 读取实际文件，列出尚缺材料，再决定本批任务。

## 文件和使用顺序

| 文件 | 什么时候用 | 怎样使用 |
| --- | --- | --- |
| `01-开发前检查表.md` | 派任务前 | 复制到你的项目资料目录，填写真实路径和环境；未确认项保留“待确认” |
| `02-开发流程规则补充.md` | 接上现有项目规则 | 只把适用条目合并进已有规则文件，保留原文；有冲突先处理 |
| `03-tdd任务卡.prompt` | 一张开发卡开工 | 填入本卡范围、AC和允许改动位置；派给实际开发角色 |
| `04-三层验收.prompt` | 一个模块的开发卡完成 | 派给独立审查角色或新会话；按三层检查出报告，修复另派 |
| `05-冻结交接.prompt` | 已验收的批次准备交付，或中途交接 | 明确“发布准备”或“未完成交接”；不能把模板运行当作发布授权 |
| `06-文档变更核对表.md` | 改需求、接口、字段、环境或安全规则 | 先查影响，再同步文档、代码和测试，记录未处理项 |
| `07-指挥Agent操作手册.md` | 第一次跟做 | 按顺序操作，内含可复制话术、检查位置和失败时的下一步 |

文件按原名保存即可。若项目已有 `prompts/03-tdd.prompt`、`prompts/04-test-review.prompt`、`prompts/05-freeze.prompt`，先对比再合并或在规则中引用实际文件，不要同时维护两份相互矛盾的规范。`.prompt` 是普通文本扩展名，不会因为放进文件夹就自动执行。

## 使用边界

- `〈待填写〉`、`〈实际路径〉` 等占位符先替换，没确认的内容不要猜。
- 保留项目现有技术栈、测试框架、目录和更具体的规则，不为套模板新装一整套工具。
- 密钥、密码、令牌不写进模板或提交。只记录配置项名称与由谁提供。
- 测试只连接明确隔离的测试环境和专用账号，先确认数据重置范围。
- Git 提交、推送、正式部署和数据库变更按你当前授权执行；复制文件不会新增权限。
- 没有子 Agent、看板或派单插件，也可以用 Markdown 任务表由主 Agent 顺序完成。不要编造 `@PM`、私有CLI或不存在的工具调用。

## 怎么判断这套文件用对了

你应能从一条需求的 AC 找到任务卡、测试用例、实际运行结果、实现差异与验收结论。不能运行时，应能看到“未验证”的原因、阻塞位置和恢复办法。

这套资料不含项目代码，因此没有可直接启动的示例应用。运行自己项目时，使用检查表里经核实的命令；不要把文章中的示例命令原样套在未知项目上。
