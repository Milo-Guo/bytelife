# ByteLife 访问统计

网站继续部署在 GitHub Pages，统计由 Umami Cloud 托管。登录 [Umami 后台](https://cloud.umami.is/)查看数据，不需要另建服务器和数据库。

`analytics.json` 的 `website_id` 为空时，页面不会加载统计脚本。填入真实网站 ID 并发布后才开始收集，无法补出接入前的访问记录。

## 第一次启用

1. 在浏览器打开 [Umami 注册页](https://cloud.umami.is/signup)，注册或登录自己的账户，选择免费 **Hobby** 方案。根据 [官方定价](https://umami.is/pricing)，截至 2026 年 10 月 26 日，免费方案支持 1 个网站、每月 10 万次事件、保留 6 个月；以后以账户显示的额度为准。
2. 在 **Websites**（网站）里添加网站，名称填 `ByteLife`，域名填 `milo-guo.github.io`。域名不带 `https://` 或 `/bytelife/`。
3. 打开这个网站的 **Edit**（编辑），找到 **Tracking code**（统计代码）。复制其中 `data-website-id="..."` 引号里的完整 ID。它是公开网站编号，不是密码或 API Key。具体入口见 [官方接入说明](https://docs.umami.is/docs/collect-data)。
4. 用 VS Code 打开 `C:\Users\guo\Documents\ByteLife-GitHub`，打开根目录 `analytics.json`，把 `website_id` 的空字符串替换为刚复制的 ID，保存。只填写 ID，不要粘贴整段 HTML。
5. 在 VS Code 的 **Terminal → New Terminal** 中运行：

   ```powershell
   python scripts/build.py
   python scripts/check.py
   python scripts/test_build.py
   python scripts/test_analytics.py
   ```

   成功时，构建显示“访问统计：已配置 Umami Cloud”，检查显示“检查通过”，两组测试最后均为 `OK`。ID 格式不对时，构建会停止并提示修正。
6. 发布这些修改需要把代码提交到 GitHub。确认本次文件后，在上述文件夹运行以下命令；这些是手动发布步骤，配置文件本身不会自动发布：

   ```powershell
   git status
   git add analytics.json scripts/site_analytics.py scripts/build.py scripts/check.py scripts/test_analytics.py .github/workflows/pages.yml README.md docs/访问统计.md
   git commit -m "接入 Umami 访问统计"
   git push
   ```

7. 在仓库 **Actions → 发布 ByteLife** 中等待最新运行变成绿色勾。用浏览器打开 [线上首页](https://milo-guo.github.io/bytelife/)，再打开一篇文章。
8. 回到 Umami 后台，选择 `ByteLife`。看到刚产生的页面访问记录，就说明接入成功。报表默认私有，保留默认设置即可；**Share URL** 会创建公开报表链接，参见 [官方说明](https://docs.umami.is/docs/enable-share-url)。

## 后台可以看什么

| 想知道的问题 | 查看内容 |
| --- | --- |
| 一共访问了多少次 | Views，页面浏览次数；同一个人打开多页会产生多次 |
| 大约有多少访客 | Visitors，按匿名标识估计的访客数，不是精确自然人数 |
| 从哪个网站进来 | Referrers，来源网站；浏览器没有提供来源时可能显示为直接访问 |
| 从哪里访问 | Countries / Regions / Cities，国家、地区或城市；取决于 IP 定位数据是否可用，代理可能改变结果 |
| 哪个时间最活跃 | 日期范围和流量趋势图，查看每日或更细的时间分布 |
| 哪篇文章最受欢迎 | Pages，按访问量查看 `/bytelife/articles/.../` |
| 有没有再次回来 | Retention，按首次访问日期分组查看随后几天的回访比例 |
| 手机还是电脑 | Devices、Browsers、Operating systems |

访客识别受 IP、浏览器变化以及匿名标识轮换影响，不能据此断言某个人的真实身份或长期访问次数。Umami 默认按月轮换匿名标识；[指标口径](https://docs.umami.is/docs/metric-definitions)和 [Retention 说明](https://docs.umami.is/docs/retention)解释了计算方式。

## 这个站点怎样发送统计

- 只有配置了网站 ID，才给首页、已发表文章、存档、迁移记录和作者页加入官方脚本。页脚会出现“访问统计：Umami”说明链接。
- 写作页、404 和草稿不加载统计；使用 `--drafts` 时，整次构建都禁用统计。写作页可以继续连接 GitHub API。
- `data-domains` 限定为 `milo-guo.github.io`，本地 `localhost` 和 `127.0.0.1` 预览不会发送访问记录。
- 页面地址不采集查询字符串和 `#` 锚点。站内搜索、JSON 和时间戳工具没有额外添加事件上报；未启用会话回放或 Distinct ID。
- CSP 只增加官方脚本 `https://cloud.umami.is/script.js` 和收集地址 `https://gateway.umami.is`；没有开放任意第三方脚本。配置文件不允许任意脚本地址。

以上脚本参数见 [官方配置文档](https://docs.umami.is/docs/tracker-configuration)，Cloud 的收集地址见 [官方说明](https://docs.umami.is/docs/bypass-ad-blockers)。

## 排除自己反复打开的访问

先确认统计已经正常工作，再在**线上网站**打开 Chrome 或 Edge，按 `F12` 进入 **Console**（控制台），手动输入：

```javascript
localStorage.setItem('umami.disabled', 1);
```

这个设置只影响当前浏览器、当前网站域名。换手机或浏览器要分别设置。恢复统计时运行：

```javascript
localStorage.removeItem('umami.disabled');
```

这是 [Umami 官方提供的方法](https://docs.umami.is/docs/exclude-my-own-visits)。

## 没有数据时检查

1. 确认访问的是线上网址，本地预览不计数。
2. 确认 GitHub Actions 已经发布本次提交，网页源代码能搜到自己的 `data-website-id`。
3. 确认后台选的是正确网站和日期范围，ID 没有复制错。
4. 按 `F12` 打开 **Network**（网络），刷新线上页面，检查 `cloud.umami.is/script.js` 和 `gateway.umami.is/api/send` 是否成功。若出现 CSP 报错，保留原始报错排查，不要直接开放所有域名。
5. 检查当前浏览器是否设置了 `umami.disabled`、是否拦截统计请求，以及网络能否访问统计服务。拦截会导致漏计。
6. 将 `analytics.json` 的 `website_id` 清空，再构建、提交并发布，即可停止以后的网站统计；这不会删除 Umami 中已有的数据。
